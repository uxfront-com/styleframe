Add a `color.focus` token for focus rings, plus five accessibility modifiers and a `position-try-fallbacks` utility. The token is a reference to `@color.primary` in the light and dark themes, emitted as `--color--focus`, and the `focus.outline-color` default now points at it, so focus rings look the same as before. If you replace the default colors, with `meta: { merge: false }` or with `colors: false` and your own `useColorDesignTokens` call, add a `focus` color, because the focus ring now references `@color.focus`. The new modifiers are `hover-capable` (`@media (hover: hover)`) and `any-pointer-coarse` (`@media (any-pointer: coarse)`) from `useMediaPreferenceModifiers`, `aria-invalid` (`[aria-invalid="true"]`) from `useAriaStateModifiers`, `readonly-attr` (`[readonly]`) from `useFormStateModifiers` and `data-loading` (`[data-loading]`) from `useOtherStateModifiers`, each with its own composable, like `useHoverCapableModifier`. The `usePositionTryFallbacksUtility` composable is registered in `useUtilitiesPreset` as `createPositionTryFallbacksUtility` and ships without defaults. Reference colors like `focus` no longer get level, shade or tint keys in the `useDesignTokensPreset` return type, because none are generated for them.
